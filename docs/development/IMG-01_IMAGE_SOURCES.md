# IMG-01 외부 이미지 장애 및 데이터 출처 조사

2026-11-27 KST · 기준 main `a1cd5dd64ff92c0e2fb3e200d26e971fc7e58b76` · PR #6 병합 확인 · 조사 시 열린 PR 0건.

**저장소 분석 완료, 원본 판정 차단.** 현재 Cloud의 HTTPS 프록시가 `sake-guide.com` 연결을 거부했다. 원본 서버의 응답, 사이트 개편 여부, 새 상품 식별자와 이용 조건은 확인 대기 상태다. DEV-01 이후 애플리케이션과 테스트 파일 변경이 없어 기존 [기준선 기록](CLOUD_SETUP.md#dev-01-cloud-기준선)을 참조했다.

## 저장소에서 확인한 기존 구조

- [목록 수집기](../../tools/src/main/java/com/sakezuki/tools/crawler/SakeListCrawler.java)는 `/sake` 목록에서 `/sake/detail/<숫자>` 링크를 모은다. [이미지 수집기](../../tools/src/main/java/com/sakezuki/tools/crawler/SakeImageCrawler.java)는 해당 숫자 `source_id`로 상세를 열고 `.sake-hero__figure img[data-src]`의 절대 URL을 가져온다. 빈 값, `noimage`, 요소 누락, 요청 예외는 모두 `null`이다. 이미지 응답의 MIME과 본문은 확인하지 않는다.
- [업데이터](../../tools/src/main/java/com/sakezuki/tools/SakeImageUpdater.java)와 [저장소](../../tools/src/main/java/com/sakezuki/tools/repository/SakeRepository.java)는 `image_checked='N'`만 조회한다. `source_id`로 `image_url`을 갱신하며, `null`이어도 `image_checked='Y'`가 된다. 따라서 기존 URL이 깨진 행과 과거 요청 실패로 `Y`가 된 행은 현 작업의 재시도 대상에 포함되지 않는다. 현재 스키마에 응답 코드, 확인 시각, 실패 사유, 라이선스 기록은 없다.
- [V1](../../backend/src/main/resources/db/migration/V1__initial_schema.sql)은 내부 PK `no`와 별개로 `source_id`를 고유 BIGINT로 저장한다. `image_url`은 nullable VARCHAR(1000), `image_checked`의 기본값은 `N`이다. [MyBatis 매퍼](../../backend/src/main/resources/mapper/sake/SakeMapper.xml)는 저장 URL을 전달하고 URL이 있는 행을 우선 정렬한다. [사케 이미지 컴포넌트](../../frontend/components/sake/SakeImage.tsx)는 브라우저에서 외부 이미지를 직접 요청하며 실패 시 로컬 대체 이미지를 표시한다.
- [V2 시드](../../backend/src/main/resources/db/migration/V2__initial_seed.sql)의 SAKE INSERT 세 문장을 오프라인으로 집계했다. **10,337행과 고유 source_id 10,337개**가 있고 모두 `Y`다. 비NULL URL은 **4,037개**로 전부 고유하고 호스트는 `sake-guide.com`이다. 확장자는 JPG 3,880개, PNG 157개다. NULL은 **6,300행**이다. 시드 통계이며 운영 DB를 조회하지 않았다.

## 개편 전후 비교와 대표 표본

기존 목록·상세 경로와 선택자는 저장소 코드에서 확인했고, 이미지 경로와 상품명은 시드에서 확인했다. URL 보유 행의 처음·중간·끝에서 의도적으로 3건을 골라 JPG와 PNG, 서로 다른 양조장과 상품군을 포함했다. 요청은 Cloud 기본 프록시와 TLS 검증을 사용했다. 사이트 홈 GET과 아래 상세·이미지 HEAD 6건 모두 CONNECT 403으로 중단됐다. curl 종료 56, `http_code=000`, `http_connect=403`이었다. 실행 상태에서 제한 정책이 적용 중이며 이 호스트는 허용 목록에 없음을 확인했다. HTTP 응답 본문, 원본의 403·404, 리디렉션 및 신규 HTML 구조는 관찰하지 못했다.

재현 예시는 `curl -sS -I --max-time 8 -o /dev/null -w 'origin=%{http_code} connect=%{http_connect}\n' https://sake-guide.com/sake/detail/17116`이다. 승인된 접속 환경에서 홈의 상품·약관 링크부터 따라가고, 표본에 대해 원래 URL과 최종 URL, 상태, MIME, canonical·상품 식별자·이미지 마크업(`src`, `srcset`, lazy-load, 구조화 데이터)을 함께 기록한다. HEAD가 지원되지 않으면 약관에서 허용하는 범위에서 해당 표본만 GET으로 확인한다. 오래된 이미지가 실패하지만 새 상세에 동일 상품과 새 이미지가 있으면 주소 변경 근거가 된다. 상세는 열리지만 기존 선택자만 사라졌으면 파서 계약 변경 근거가 된다. 접근 제어·삭제·상품 변형과도 구별한다.

4,037건은 우선 검토할 후보군이다. 일부 기존 URL 유지, 동일 상품의 신규 이미지, 다른 출처로 대체, 단종·미매칭이 모두 가능하다. 확인된 복구 건수와 복구율은 산정할 수 없다. 6,300건도 당시 `null`의 사유를 구별할 수 없어 상품 이미지가 없다고 확정할 수 없다.

## 이용 조건과 대체 출처

현 세션에서 공식 약관, 데이터 제공 정책, 연락처, 이미지별 권리자를 읽을 수 없었다. 따라서 공개 표시, 자동 조회, 파일 복제, 리사이즈·형식 변환, R2 저장·캐시, 앱 재배포, 상업적 이용, 상품 데이터 사용 범위를 모두 미확인으로 기록한다. 공개 열람 가능 여부와 각 이용 권한은 별개다. 재조사 시 운영자가 연결한 공식 약관의 URL·버전·확인일, 허용 범위, 출처 표기와 삭제 대응, 제3자 사진 권리 예외를 기록한다. 약관과 robots.txt도 각각 확인하되, 크롤링 관련 지시만으로 저작권 허가를 판단하지 않는다. 확인되지 않은 자산은 운영 복제 대상에서 보류한다.

| 출처 | 장점 | 선행 조건과 제약 |
| --- | --- | --- |
| 기존 사케 가이드 링크 | 카탈로그와의 연속성이 있고 기존 ID가 남아 있을 가능성 | 상세·이미지 주소 및 외부 표시 조건 확인. 핫링크는 원본 가용성에 의존하고 저장·재배포는 별도 권한 필요 |
| 양조장 공식 이미지 | 제조사 이름과 제품 변형 확인에 유리하고 라벨 최신본에 접근할 가능성 | 양조장별 허가 및 촬영자 권리 확인. 용량·라벨 개정·계절 상품 매칭과 자료 공백 처리 필요 |
| 정식 데이터 제공 계약 | 안정적인 식별자·파일·갱신·삭제 조건을 계약에 명시 가능 | 커버리지, 비용, 변환·CDN·상업 이용 범위, 종료 시 삭제 의무 검토 |
| 자체 촬영 또는 사용 허가가 명확한 이미지 | 허가 기록이 있는 자산부터 적용 가능 | 촬영 및 검수 비용, 라벨·상표 관련 조건 확인. 자료가 없는 동안 로컬 대체 이미지 사용 |

## IMG-02 및 IMG-03 실행 순서

1. **IMG-02 표본과 증거 수집.** 승인된 접속과 이용 범위에서 위 표본을 확인하고, 비NULL·NULL, 동명 상품, 용량·라벨 변형과 단종을 추가 소량 검토한다. 각 행에 내부 `no`, 기존 `source_id`, 원본·신규 canonical URL과 ID, 양조장·브랜드·일본어 제품명·규격, 증거 링크, 확인일 및 검수 결과를 기록한다.
2. **IMG-02 매핑.** 공식 대응표나 상세 리디렉션을 우선 확인한다. 숫자 재사용 여부는 제품과 양조장 대조로 확인한다. 이름 정규화는 후보 검색에 사용하고 유형·정미율·원료·용량·JAN 등으로 변형을 확인한다. 확인된 일대일, 일대다·다대일 충돌, 미매칭을 남기고 모호한 후보는 수동 검수한다. 기존 `source_id`를 덮어쓰기 전에 출처별 문자열 ID와 내부 `no` 연결을 별도로 설계한다.
3. **IMG-03 합성 데이터 검증.** 먼저 격리 환경에서 출처, 매핑, 권리 근거, 원본 URL, 해시, MIME·크기, 자산 버전·저장 키·처리 상태 설계를 검증한다. 실제 원본 재사용은 권리와 매핑 확인 후 진행한다. 수집 시 승인된 호스트·리디렉션·요청률과 바이트 한도를 적용하고 이미지 시그니처를 확인한다.
4. **IMG-03 저장과 전환.** dry-run으로 복구 가능 후보와 제외 사유를 출력한다. 동일 입력은 멱등 처리하고 체크섬으로 중복을 찾아 출처 기록은 보존한다. 업로드 검증이 완료된 자산만 표시 경로를 전환하고, 중간 실패·재시도·고아 객체·삭제 요청·이전 버전 롤백을 합성 데이터로 확인한다. 새 Flyway 버전, R2 버킷·접근 정책, 비용과 운영 실행은 후속 승인 범위에서 다룬다.
