## P1 인증 세션 경계

이전 구현은 지연된 401을 최신 모듈 전역 Bearer로 재시도했다. Antigravity는 격리 MySQL에서 계정 전환 이후 이전 제보가 새 계정 소유로 커밋된 것을 관찰했다. 업로드의 다른 계정 재실행도 확인했다.

공용 Axios 요청은 최초 전송 직전에 세대와 회원 번호를 동기적으로 결합한다. 응답 및 재시도에서 그 값을 검사한다. 같은 세대·회원의 정상 토큰 갱신은 기존 요청을 한 번 재시도한다. 세션 신호를 Axios 호출자의 신호와 함께 연결하며, 수동 결합 환경에서는 완료·취소 때 리스너를 해제한다. 응답 성공도 현재 세션에 속해야 한다. 세션 전환 전에 서버에 도착한 요청은 이전 회원의 트랜잭션으로 남을 수 있다.

로그인·로그아웃·OAuth 교환·소셜 가입은 이전 세션을 즉시 분리한다. 로그아웃 서버 실패 후 클라이언트 상태는 익명으로 남는다. 서버 쿠키 폐기는 성공 응답으로 확인하며 메모리 상태를 이전 값으로 되돌리지 않는다. 새 페이지 초기화는 서버 쿠키 상태를 확인하는 별도 동작이다. 각 갱신 Promise는 세대와 소유권을 확인하고, 오래된 finally는 새 Promise를 지우지 않는다. 쿠키 전송 경로는 Web Locks 아래 계속 직렬화한다. 이미 전송한 쿠키 회전은 완료시키되 상태 반영에 사용하지 않을 수 있다. 후보 JWT로 직접 /me를 확인하고 시작 시 회원 번호가 있었다면 동일 회원이어야 수락한다. 공유 쿠키로 다른 회원이 반환되면 메모리 세션을 종료한다. 서버에서 이미 발급된 JWT의 기존 만료·검증 정책에는 변화가 없다.

익명 전환 후 fallback은 같은 세션의 일반 갱신 실패에서 구체적인 공개 GET만 대상으로 한다. 명시적 로그아웃, 새 로그인 및 회원 불일치의 세대가 이어지면 이전 응답을 폐기한다. 유료 추천 준비 중의 이력 확인과 키 계산 후, 실제 유료 전송 직전에 다시 세대를 검사한다. 기존 멱등 키 저장에는 사용자 입력 원문이나 토큰을 추가하지 않는다. 화면의 이동·알림·캐시·첨부 및 Blob은 세대와 컴포넌트 수명을 재검사한다. 세대 변경 때 개인 쿼리를 정리하고, 제보 화면의 회원 키에 세대도 포함한다.

## P2 관리자 목록 조회

페이지용 50건과 다음 페이지 판정 1건을 먼저 고르고 V14 `(submission_id,id)` 인덱스로 `MAX(id)`를 조회한다. 상세는 같은 최신 작업 계약이며 쓰기용 잠금 조회는 기존 제보 행만 대상으로 한다. 이름의 JSON null 처리, 상태 및 CREATED/UPDATED 정렬과 ID 보조 정렬을 유지한다.

격리 MySQL 8.4.13에서 같은 JDBC 연결로 조회 변형을 번갈아 준비 10회, 측정 51회씩 실행했다. 출력에서 실제 51행을 읽었다. 표는 투영을 ID 두 열로 줄여 최신 작업 조회 비용을 비교한 결과다.

| 합성 데이터 | 기존 정렬 LIMIT | MAX만 적용 | 최종 페이지 후 MAX |
| --- | ---: | ---: | ---: |
| 제보 55건, 작업 54건 | 1.357 ms | 0.845 ms | 0.907 ms |
| 제보 200건, 작업 1,800건, 현재 페이지에 작업 없음 | 22.094 ms | 1.471 ms | 1.497 ms |
| 제보 200건, 작업 1,800건, 현재 페이지에 작업 있는 제보 3건 | 1.267 ms | 1.205 ms | 1.231 ms |

작은 조건에서 기존 계획은 PRIMARY 역방향 탐색 55회, 평균 48.7행을 보였다. 큰 조건의 작업 없는 페이지에서 기존 계획은 51번 각각 1,800행을 탐색했다. 수정 계획은 제보 키가 같은 이력만 커버링 인덱스로 읽는다. 작업이 많은 제보의 구간 내부 행은 집계 비용으로 남는다. 혼합 페이지에서는 기존 옵티마이저도 커버링 인덱스를 선택했다. 최종 계획은 서브쿼리에 전달하는 제보 후보를 페이지 범위로 제한한다. 운영 트래픽을 측정한 값은 아니다.

## P3 및 인수인계

320px에서 접힌 숫자 필드를 열어도 상위 그리드와 숫자 입력이 사용할 수 있는 폭으로 줄어들게 했다. 범위 오류가 발생하면 상품 세부 정보를 열고 최초 오류 입력으로 이동한다. 표시 및 만료는 공통 날짜 파서가 UTC·Z·offset을 구분하며 잘못된 날짜는 대체 표시 또는 명시적 만료 오류로 처리한다.

양조장·브랜드 표시명은 UGC-03B의 리비전 비교 계약으로 인계한다. READY 업로드의 비활성 회원 응답 경계, 별도 JVM 간 업로드 임대, 새로고침 후 초안 복원은 기존 범위를 유지한다.

새 독립 QA는 별도 탭의 쿠키 교체, 성공 응답 및 갱신 지연, 유료 권한 경계, 각 쓰기 경로의 계정 전환, 최신 작업 조회의 무작업률 및 이력 집중도에 초점을 둔다. CI와 로컬 검증 개수는 PR에 최종 HEAD와 함께 기록한다.
