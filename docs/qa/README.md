# 검증과 독립 리뷰

1. PR의 실제 base/head 및 전체 SHA를 확인하고 해당 변경과 직접 의존성을 검토한다. GitHub Checks에서 실행 이벤트·대상 SHA와 결과를 확인한다. GitHub가 만든 PR 검증용 병합 커밋을 검사했다면 그 SHA와 PR head를 함께 기록한다.
2. [기존 CI](../../.github/workflows/verify.yml)는 프론트 단위·정적 검사·빌드·분리 MySQL과 Chromium·Linux Docker HTTP/HTTPS를 실행한다. 같은 SHA와 환경에서 유효한 결과는 재사용한다. 실패 원인을 파악하고 수정 후 해당 범위를 재검증한다.
3. 독립 리뷰는 작성자와 분리된 리뷰어가 필요한 경우에 요청한다. 인증·차감·마이그레이션·공개 경계가 달라지거나 CI가 덮지 못한 사례를 우선한다. Antigravity 등은 선택 사항이다. 별도 리뷰 자동화는 현재 SakeZuki에 없다. 요청·접수·skip·실제 제출과 reviewed SHA를 구분한다.
4. 보고에는 PR URL, 전체 SHA, 검토 범위, 격리 환경, 실행 명령, 기대/관찰 결과, 심각도, 미검증 범위를 포함한다. 완료 시 head를 다시 확인한다. head가 바뀌면 이전 증거로 표시한다. 승인된 외부 게시 경로가 없으면 작업 결과로 전달한다.
5. 미해결 차단 결함 또는 근거가 빠진 요구사항이 있으면 판정을 보류한다. 증거가 충돌하면 같은 SHA의 코드와 격리 재현을 우선한다. CI/QA 성공은 병합 또는 배포 승인이 아니다.

## 독립 QA 요청 예시

> 지정한 SakeZuki PR의 현재 head를 먼저 확인해 줘. AGENTS.md의 경계 안에서 변경 코드와 직접 의존성을 검토하고, 필요한 검증만 합성 데이터·Mock·분리 DB로 실행해 줘. CI에서 읽은 결과와 직접 실행한 결과를 구별하고, 확인한 전체 SHA·근거·미검증 범위를 반환해 줘.
